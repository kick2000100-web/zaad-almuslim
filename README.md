# حالة التنفيذ

تمت إضافة بنية تشغيل فعلية للـ Backend وSQLite والمصادقة وواجهات المحتوى والتقدم والمراجعة. قبل الإنتاج يجب تشغيل `npm install` ثم `npm run check` ثم `npm run seed`، مع ضبط `.env` وعدم استخدام كلمة مرور الإدارة الافتراضية.

## التشغيل

```bash
cp .env.example .env
# عدّل JWT_SECRET وADMIN_PASSWORD
npm install
npm run check
npm run seed
npm start
```

افتح `http://localhost:3000`.

## المتاح فعليًا

- تسجيل وتسجيل دخول JWT مع bcrypt.
- صلاحيات server-side للأدوار: user وeditor وreviewer وcontent_manager وadmin.
- SQLite مع جداول المستخدمين والمحتوى والتقدم والمحاضرات وسجل التدقيق.
- API للمحتوى: القرآن كبيانات سور فقط، الأذكار، الحديث، المحاضرات، التفسير، الفقه، الدورات.
- بحث موحد نصي مع pagination بسيطة.
- حفظ تقدم العبادات ومشاهدة المحاضرات.
- إضافة ومراجعة محتوى من API الإدارة.
- rate limiting، استعلامات parameterized، ورسائل أخطاء عامة.
- PWA وواجهة offline الموجودة في مجلد public.

## قيود صريحة

المحاضرات والبيانات الدينية المزروعة للمراجعة وليست ترخيصًا للنشر. لا توجد نصوص قرآن كاملة أو ملفات صوت وفيديو مضمّنة. الصوت والفيديو يحتاجان روابط حقيقية مرخصة. لا يوجد AI أو مزامنة بريد أو استعادة كلمة مرور أو تخزين ملفات حتى تتم إضافة مزود خارجي وخادم مهام مناسب.

## API

راجع `docs/API.md`. جميع عمليات التقدم والإدارة تحتاج `Authorization: Bearer <token>`.

## الإنتاج

استخدم HTTPS، سر JWT عشوائيًا، قاعدة بيانات ونسخًا احتياطية خارج المستودع، CORS محدودًا، مراقبة أخطاء، ومراجعة علمية لكل محتوى قبل تغيير حالته إلى `verified`.
